TL;DR

结论：lg 的目标（绝大多数程序不需要 GC、开发者不写 Rust 式 lifetime）在 2025–2026 年已经有多条被验证过的技术路线，最可行的组合是「OxCaml modes 式的 region/escape 推断 + Perceus 式精确引用计数（FBIP）+ Lobster 式自动 owner/borrow 推断」，后端通过“生成 OCaml 源码”复用 byte / native / js_of_ocaml / wasm_of_ocaml / Melange 五条编译路径，并在 OxCaml 目标上把推断结果直接落成 local / stack_ 标注，由 OxCaml typechecker 二次验证。

关键设计判断：

  • 不做 GC-free-only 语言。采用三层内存模型：Local（region/栈分配）、Owned（唯一引用，确定性析构）、Shared（GC 堆）。推断不出来的一律落 Shared —— 正确性永远由底层 OCaml GC 兜底，性能由推断质量决定。这是与 Rust 的本质差异：Rust 把 memory 作为正确性前提，lg 把 GC 作为兜底、把 ownership 当作优化和 API 约束工具。
  • 不写 lifetime 不等于没有 lifetime 语义。OxCaml 已证明：region 抽象 + mode 推断可以让 typechecker 自动证明“值不逃逸”，程序员只在需要 API 约束时才写 @ local。Lobster 进一步证明 owner/borrow 推断在真实项目里只需极少量人工干预（作者报告几十个中型程序只有 2 处需要改动）。
  • 语言本身是 fresh design，不是 lg v1 的迭代。lg v1 的教训（静态化的 Clojure、.mli sidecar、closed-variant 数据建模）值得继承；v2 的增量是内存语义层。

2. OxCaml：locality modes 与 stack allocation 详解

OxCaml（Jane Street 的 OCaml fork）在普通 OCaml 的类型之外叠加了一套 mode 系统：mode 不描述数据形状，描述值的属性（能否逃逸、是否被别名、能否跨线程）。这是 lg 最重要的参照系 —— 它证明了在 ML 家族语言里，“不逃逸 ⇒ 可栈分配”可以完全由编译器推断。

2.1 Mode 轴

OxCaml mode 轴
轴值域（强 → 弱）追踪什么
localityglobal → local值能否逃逸出它的 region（决定可否栈分配）
uniquenessunique → aliased值是否有多个引用（决定可否原地更新）
linearitymany → once值被使用的次数（once ⇒ 至多一次）
portabilityportable → corruptible → shareable → nonportable能否跨线程/capsule 传递
contentionuncontended → shared → corrupted → contended值当前是否被别的 capsule 持有
yield / fork / statefulness / visibility各自两至四档更细的并发与效果约束（v2 暂不需要）

每条轴都是半格（meet 向下、join 向上），值永远可以被“弱化”（weaken）到更弱的 mode：global 值可以当作 local 用，unique 值可以当作 aliased 用。mode 之间有蕴含：global ⇒ aliased · many · forkable · unyielding。typechecker 的任务是推断每个位置最强的可证明 mode。

2.2 Region 与 stack allocation 规则

  • Region 是静态概念：函数体是一个 region；while/for 循环体、lazy、顶层 module binding 各自也是 region。Region 嵌套；最外层 region（整个文件）永不结束，global 值住在那里。
  • 栈分配不写死在 call stack 上，而是写在与 minor heap 同构的独立 region 栈上，因此 local 返回值不需要拷贝（exclave_）。
  • stack_ 关键字强制栈分配：分配逃逸时是编译错误而不是悄悄回落到堆。没有 stack_ 时编译器自行决定，安全就栈分配，否则堆分配——这正对应 lg 想要的“silent optimization”语义。
  • local mode 标注≠强制栈分配，它只是禁止值逃逸 region；编译器继而可以自由选择栈分配。推断不写标注时已经是这个行为。
  • Mode crossing：不分配在内存的类型（int、bool 等立即数）可以无条件穿越 locality 轴 —— local int 可以当 global 用。lg 里要保留这条规则。
  • 不可栈分配：modules、exception（global 才能 raise）、objects。

2.3 函数类型上的 mode：四种函数

a → b、a @ local → b、a → b @ local、a @ local → b @ local 是四种不同的类型。参数位的 local 是“允许调用方传 local 值”；返回位的 local 是“返回值 local 到调用者的 region”（即 exclave_ 的效果）。这给了 API 作者双向约束能力 —— with_file 式资源管理的静态化保证（fd 不许被 stash）就是 covariant local 参数的典型用法。

2.4 推断的实际能力与边界（重要）

  • 推断不跨文件边界：没有 mli 时，所有对外可见的函数参数默认 global。有 mli 时以 mli 为准。这直接决定了 lg 的模块设计必须为每个函数生成/缓存 mode 签名。
  • local 参数可以出现在任何位置，包括高阶函数；闭包捕获 outer-local 值是允许的（值不属于内层 region，所以逃逸内层 region 无碍）。
  • uniqueness 目前主要用于 API 约束与 future overwriting；OCaml 有 GC 兜底，所以“放弃 ownership”总是安全的——这条性质让 OxCaml 的 uniqueness 比 Rust 的 ownership 弱但好用得多，lg 要继承这个取舍。
  • Modality（@@）描述容器与元素之间的 mode 映射：record 字段 @@ global 意味着取出时是 global，无论容器本身 mode 如何。lg 的 record/map 访问规则照此建模。
设计决定：lg 的 Local 层直接采用 OxCaml region/escape 模型，但不引入 mode 概念到 surface syntax —— 推断结果落在 IR 注解上；当用户需要 API 约束时才通过 ^:local / ^:once metadata 暴露。

3. Perceus / FBIP：让“绝大多数数据不需要 GC”的关键算法

Perceus（PLDI'21，Reinking / Xie / de Moura / Leijen）是目前最完整的“自动精确引用计数 + 原地更新”方案，已落地于 Koka、Lean 4（生产级）、Roc。lg 的 Owned 层基本是 Perceus 的移植。

3.1 算法骨架

  1. dup/drop 插入：在显式控制流 IR 上，对每个绑定在最后使用点之后插入 drop，对每个共享（第二个及以上）使用插入 dup。产生的程序 garbage-free：任何死亡对象立刻被释放，只有 live 引用被保留。
  2. Borrow inference：只“看一眼”的参数标记为 borrow，避免 dup/drop。Koka 的实现里这一步消掉了绝大多数 RC 操作。
  3. Drop specialization：匹配完不再需要的字段在对应分支就地 drop，而不是把整个 drop 延后到统一出口 —— fast path 上省掉大量计数操作。
  4. Reuse analysis：对象在构造点标记 reuse token；如果某对象的 refcount 为 1 且紧随其后的操作是“析构 + 立即构造同尺寸对象”，就用它的内存。这是 FBIP 的基础。
  5. Reuse specialization：把“先 drop 再 alloc 同形状”优化成“就地写字段”，消掉 in-place update 本身的分配。

3.2 FBIP（functional but in-place）

FBIP 的语义：程序写出来是纯函数的，运行时如果某次更新操作的输入 refcount==1，就原地覆写；否则拷贝再改。用户不需要任何标注，正确性由拷贝语义保证。Roc 把这一点做成了语言级承诺（opportunistic mutation）；Koka 用它实现了接近 C 的 in-place 算法（例如 map/filter 在唯一输入时零分配）。

对 lg 的意义：Clojure 的 transient 语义可以全自动获得 —— 只要输入向量的 refcount 是 1，conj/assoc 就地改 RRB/HAMT 节点；refcount>1 时退化到 path-copying。Clojure 的 transient!+persistent! 手写 ceremony 变成编译器自动优化。

4. Lobster：最接近“自动 ownership 推断”的现存证据

Lobster（Wouter van Oortmerssen）做了一个语言设计圈少有人做的实验：把现成的 runtime RC 语言加上编译期 owner/borrow 推断，然后看程序要不要改。结果：几十个中型游戏原型里只有 2 处需要手动改动。这直接回答了 lg 的第一个问题 —— 自动 ownership 推断不仅可行，而且在真实代码里成功率极高。

Lobster 的算法要点：

  • 每个堆分配选一个 owner（通常是第一个接收它的变量/字段/vector 元素）；
  • 从 owner 出发，后续所有 use 尽量标为 borrow（不产生 RC 操作）；
  • 某处确实需要拥有时，插入局部 inc而不是报错 —— 与 Rust 的策略正好相反：Rust 拒绝，Lobster 降级到运行时 RC；
  • 无法静态证明借用的存活关系时，也降级到 RC；
  • Cycle 由运行结束时的 leak 报告兜底，要求程序员手动打破。

对 lg 的移植价值：owner/borrow 推断不需要 lifetime 标注，因为它求的是“这个 use 是不是 owner 的最后一次读”，是流分析而不是类型层问题。lg 把这个过程放在 mode inference 之后的 IR 上做，与 Perceus 的 borrow inference 是同一个 pass 的两面。

6. Clojure 语法与数据结构：静态化时保什么

6.1 核心数据结构的真实实现

  • PersistentVector：32 路 trie，尾插 O(log₃₂n)≈O(1)；严格版本用路径拷贝，relaxed 版本（RRB-tree）支持 O(log n) concat/slice。lg v1 用 Rrbvec.t，lg 沿用并叠加 uniqueness → 原地更新。
  • PersistentHashMap：HAMT（hash array mapped trie）；JVM 新版为 CHAMP。静态类型 lg 中同 key/value 类型时可以直接用 OCaml 端 ImMap-style HAMT；keyword-keyed map 走 interned keyword，hash 常数化。
  • PersistentHashSet / SortedSet / SortedMap：基于 map 或平衡树；Datascript 的 persistent-sorted-set 已有 OCaml 移植可直接复用。
  • List / Seq / LazySeq：list = OCaml 原生 'a list；seq 是延迟视图，lazy 本身需要共享 ⇒ Shared 层。
  • Transient：Clojure 用 editable flag + 单线程 token；lg 用 uniqueness 自动替代 —— (into [] coll) 内部循环拿到的中间向量 refcount==1 时自动是 transient 语义。

6.2 core 函数集的静态化重述

Clojure core 是动态 API（assoc 接受任意 map-like），lg 需要静态版本。取舍已经在 lg v1 上验证过：closed sum 的 collection 抽象（vector / map / set / list / seq 是五个不同类型，不是五个接口实现），重载用多 arity defn 表达，keyword 做 (:k m) 调用糖但要求 m 的静态类型已知是 record 或 keyword-keyed map。类型层不引入 JVM 式 protocol dispatch，而是 traitless overloading：编译期把 (assoc m k v) resolve 成 Map.assoc 或 Record.assoc。

6.3 必须砍掉或改造的 Clojure 语义

  • atom/ref/agent：保留 atom（= OCaml ref cell），但存的内容只能 Shared 或立即数；不允许 Owned 值进 atom（违反确定性析构）。
  • lazy-seq：保留但只能 Shared —— thunk 捕获会让局部推断失败，不值得为它放宽。
  • volatile!/transient：语义由 uniqueness 推断自动提供，不再暴露给用户。
  • defprotocol/defrecord dynamic dispatch：改成编译期 resolution；runtime protocol 用 first-class module 或闭包 record。
  • *warn-on-reflection* 类问题不存在：本来就全静态。

7. Implicit modules：文件即模块

“Implicit modules”取 OCaml 路线：每个 .lg 文件就是一个模块，模块名从路径推导，源文件里不写 module 声明；ns 表单可选 —— 省略时用路径，写了则以 ns 为准（但必须与路径一致，否则报错）。这同时满足 Clojure 习惯（显式 ns）和 OCaml 习惯（文件系统即命名空间）。

  • 路径规则：src/foo/bar.lg → Foo_bar（OCaml 模块命名）；引用时用 foo.bar/f 或 (:require [foo.bar :as b])。
  • visibility：默认全 public；需要私有 API 时加一个相邻 .lgi（继承 lg v1 的 sidecar 思想，但用 lg 语法而不是 OCaml mli）。lgi 同时是 mode 签名的缓存点 —— 解决 OxCaml “推断不过 mli 边界”的痛点：我们把推断结果写进 lgi，下游模块直接用。
  • 子模块：目录即 module pack（OCaml -pack 的现代等价物 = 目录命名空间）。不支持文件内嵌套 module —— 保持“implicit”承诺纯粹。
  • 没有 functor / first-class module：需要时用 record-of-functions（Clojure 习惯）或行级 module type 语法（保留给 v3）。

8. 类型系统：HM 推导 + 可选标注

目标是 Hindley-Milner + let 泛化 + value restriction（OCaml 同款，经过 30 年验证），标注只在三种地方有意义：

  • API 边界：(defn f ^{:sig (fn [int -> int])} [x] ...) 或 lgi 文件 —— 控制对外契约，跨模块推断边界。
  • 消歧：当同名字段在不同 record 间产生歧义时标注提示。
  • Mode/API 约束：^:local、^:once、^:shared metadata —— 覆盖推断结果，但只允许往更强约束方向覆盖（函数参数从 global 加强为 local 是 API 承诺收紧，合法；反之非法）。

几个关键设计点：

  • Record vs map：lg v1 已经解决 —— keyword-keyed map 与命名 record 是两个类型族，record 的字段访问是 O(1) 直接读，map 是 HAMT lookup。lg 继承这个分裂，不加 row polymorphism（复杂度不值）。
  • 多 arity defn：编码为嵌套 pair 签名（lg v1 的 (unit->a) * ((a->b) * unit) 形式）或直接 ADT dispatch —— v2 采用后者，更干净。
  • 变参 & rest：翻译成 'a list -> ...，语法糖不变。
  • 泛型：HM 的 'a 足够；不允许 ad-hoc overloading（与 Clojure 的 ifn/invoke 魔法切割）。需要多态行为时用 deftype + 方法表（record of functions）。

10.1 三层内存模型（核心）

Local 不逃逸当前 region escape analysis 证明：不返回、不进 escaping closure、不进 ref、不进 Shared 容器 region 结束即回收 普通堆分配 + 注释；OCaml minor GC 兜底 @ local / stack_，真实栈分配
Owned 唯一引用、确定性析构 逃逸出 region，但 ownership 分析证明任一时刻只有一个 owner；类型不含 ref/atom/lazy 最后使用点 drop（编译期插入） 普通堆分配，drop 实际是 no-op（GC 兜底）；但 IR 上保留 drop 标记供 OxCaml/Roc-style RC 后端用 @ unique；允许 overwrite_/原地更新
Shared 任意别名、可能成环 默认回落层；ref/atom/lazy/第一-class module 容器、跨线程值 OCaml GC 普通堆分配 普通堆分配

对应“绝大多数程序不需要 GC”：Local + Owned 两层都不触发 GC；只有 Shared 走 GC。实测目标（参考 Lobster 报告）：典型函数式业务代码 90%+ 分配落在 Local/Owned。

10.3 Surface syntax 草样（示意）

;; hello.lg — implicit module hello
;; (ns hello) 可选；路径即模块

(defn sum
  "Total of a vector of ints."
  ^{:sig (fn [(vec int) -> int])}     ; optional annotation
  [xs]
  (fold + 0 xs))                       ; xs is borrowed; fold's callback gets local xs

(defn make-point [x y]
  {:x x :y y})                          ; {:x :y} keyword-keyed record, all Local unless returned

(defn dist ^:local [p q]                ; ^:local = promise not to escape p/q
  (let [dx (- (:x p) (:x q))
        dy (- (:y p) (:y q))]
    (sqrt (+ (* dx dx) (* dy dy)))))    ; intermediate record/tuple is Local, stack-allocated

(defn process [req]
  (let [resp (handle req)]              ; resp Owned if handle returns owned
    (log! resp)                          ; borrow
    resp))                               ; move: ownership transfers to caller

10.4 “无 GC” 的诚实评估

  • 纯函数 + 树/图无环结构 ⇒ 完全 Local/Owned，GC 只在 Shared 层跑：这类程序跑起来 GC 几乎不工作（与 Koka/Lean 相同结论）。
  • 有 cycle 的结构（图、双向链表、相互引用的 record）：类型系统在编译期拒绝 Owned 层，程序员要么显式落到 Shared（^:shared），要么用 id/引用打破环 —— 这是 lg 对比 Clojure 新增的限制，比 Rust 的 lifetime 标注负担轻得多但非零。
  • lazy / atom / 线程共享：默认 Shared。想要 Owned 化需要显式约束 —— 边界清晰。
  • wasm_of_ocaml 的 WasmGC 与 lg Shared 层是天然匹配，浏览器/云场景下“GC”不再是缺点而是特性（sandboxed managed memory）。

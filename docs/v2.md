# lg v2 — design and work plan

Status: all items shipped — §1–§4, §6 and §7 are done. §5 (OxCaml
end-to-end) is emit-side complete pending an OxCaml switch. Builds on v1 (see design.md §9 for the standing
decisions: no `defprotocol`/`defmulti`, `dyn` stays confined, implicits
are a compiler feature not an OCaml dependency).

Ordered by priority; each item lists surface syntax, semantics, the
implementation path, and how we verify it.

## 1. Implicit parameters (dictionary-passing elaboration) — DONE

Shipped. Static, typeclass-style polymorphism without protocols or
multimethods — dictionaries resolve at call sites, zero runtime cost.

**Surface.**

```clojure
;; a trailing param marked ^:implicit takes a dictionary type key
(defn show [x ^{:implicit (fn [int] string)} s] (s x))

;; `^{:implicit T}` on a def/let registers an instance in scope
(def ^{:implicit (fn [int] string)} int-show (fn [^int x] (str x)))

(show 42)                                   ;; resolves int-show by type
(show 42 (fn [^int n] (str "n=" n)))        ;; explicit arg always wins

;; cross-module: implicit entries merge only on request
(ns main (:require [util :as u :implicits true]))
```

Resolution rules:

- Implicit params must be trailing; the inferred `TImplicit` wrapper
  makes them transparent inside the body (calls/unify/printers see the
  dictionary type itself).
- At each call site supplying exactly the explicit params, the
  inferencer looks each implicit param's type up in the *implicit
  table* — `(type key -> value thunk)` entries, innermost wins — and
  appends the resolved value to the argument list.
- Entries come from `^{:implicit …}` def/defn/let bindings; `let`
  entries are scoped (saved/restored with the env).
- `[ns :implicits true]` on a require merges that module's exported
  `^{:implicit}` defs into scope; `.lgi` files list them as
  `(implicit name TYPE)` so interface-only deps carry the same table.
- No instance → compile error naming the needed dictionary type.

**Gotcha.** A dictionary impl whose params go through `str`-style
`any`-typed builtins genuinely has type `any -> …` — annotate impl
params (`(fn [^int x] …)`) so the declared key and impl agree, or the
emitted OCaml will be `dyn`-typed where a concrete arg is expected.

**Verify.** `test/implicit.lg` (register, resolve, explicit override,
let-shadow, value use), `should_fail/implicit.lg` (missing instance),
cross-module run in test.sh.

## 2. `.lgi` interface files (mli-style) — DONE

`.lgi` is lg's `.mli`: the file that *is* the module's interface. It
serves two purposes at once — cross-file mode signatures and the
private/public boundary — with **no `private`/`export` annotations in
`.lg` files**.

- `lg modes` (or `lg check --emit-lgi`) generates `<file>.lgi` next to
  each `.lg`: per def its name, value type, and mode signature
  `{ params : [mode], ret : mode, escapes : bool }`. Hand-written or
  hand-edited `.lgi` is equally valid and wins over generated output.
- `lg check`/`emit`/`build` on a *consuming* module reads the
  dependency's `.lgi` (when present and fresher than the `.lg`) for the
  mode signature instead of assuming every external binding escapes.
- **Export rule**: a def is exported iff it is listed in `.lgi`. A `.lg`
  file with no `.lgi` exports everything (current behavior); with an
  `.lgi`, anything not listed is private — referencing it from another
  module is a compile error. To hide a concrete type, the `.lgi` entry
  can give an abstract type instead of the real one.
- The generator is additive: `lg modes` regenerates entries for defs it
  can see, preserving hand-edited entries for defs it cannot.

**Interface-first** (Anil Madhavapeddy's mli/agentic workflow): a
consumer's `lg check`/`lg modes` is satisfied by a dep that has an
`.lgi` and no `.lg` at all — `(:require [money])` typechecks against
`money.lgi` alone; `emit`/`build` is where the implementation must
appear. Write interfaces first, let the client typecheck, then fill in
implementations in dependency order.

**Verify.** `util.lg` helper stays `Local` when compiled through `.lgi`
(assert via `lg modes` diff); `should_fail/private.lg` hides a def by
omitting it from `.lgi` and must fail `lg check`; a consumer of an
`.lgi`-only dep checks but fails `emit`.

## 3. OxCaml backend — DONE (emit-side)

`lg emit|build --backend=oxcaml` lowers inferred modes to real OxCaml
annotations in the emitted `.ml`; `--backend=ocaml` (default) is
unchanged and stays the verified path.

- `Local` allocation sites emit `(stack_ …)`; non-escaping `let`
  bindings emit `let x = (local_ …)`; non-escaping `fn` params emit
  `(local_ x)`.
- `Owned` bindings emit `let x = (unique_ …)`.
- `lg build --backend=oxcaml` prints a notice that the downstream
  compile needs an OxCaml-capable `ocamlfind` (flambda2 toolchain) and
  still emits the annotated file — installing that switch is the
  environment-gated piece (`LG_OXCAML=1`), at which point the OxCaml
  typechecker re-verifies our inference.
- Per-param escape flags reused from `Modes.is_escaping_use` /
  `occurs_in_result` — the same analysis that fills `.lgi :escapes`.

**Verify.** `test.sh` emits `test/oxcaml.lg` with `--backend=oxcaml`
and asserts `stack_`/`local_`/`unique_` markers appear; vanilla build
+ run of the same file unchanged.

## 4. FBIP / Perceus-owned reuse — DONE

Shipped as builder lowering on the vanilla OCaml backend (clj-core has
no transient API — the unique-owner property is exploited by emitting
one mutable builder + a single freeze instead of n intermediate
persistent values).

- **Ownership criterion (emit-time).** An update spine
  `conj / assoc / dissoc / into / pop / update / disj` lowers when its
  chain root is a fresh collection literal, or a binder that is used
  exactly once (`bused <= 1`), is not captured (`bmode = Local`), and
  was bound to a literal (`blit`). Anything else stays persistent —
  shared values are never mutated.
- **Emission.** `Lg_rt` builders: `vbuilder` (growable array →
  `Clj_core.Vec.of_array`), `mbuilder`/`sbuilder` (Hashtbl →
  `Map.of_list`/`Set.of_list`). The whole spine coalesces:
  `(conj (conj (conj [1] 2) 3) 4)` emits one `vb_of_arr` + 3 `vb_push`
  + one `vb_freeze`. `into` on a literal root emits the source's
  `Vec/List/Set.iter` into the same builder.
- **Soundness.** The reuse criterion is a syntactic use-count, not a
  heuristic: a binder counted more than once never lowers, so aliasing
  is impossible by construction. A `transient`/`persistent!` manual
  surface is deferred — no clj-core primitives exist for it.

**Verify.** `test/fbip.lg`: literal-rooted vec/map/set chains, once-used
binder chains, shared binder staying persistent (original value
observed intact), `pop`/`update` ops through builders.

## 6. `--strict` dyn mode — DONE

`lg <cmd> --strict`: a literal that widens to `any` (heterogeneous vec,
map, or set) is a compile error unless the author opted in with a
`^any`-family annotation (`^any`, `^(vec any)`, `^(map a b)` with an
`any` side). Effect: every `any` in the program is one the author wrote
down. Error: `strict: heterogeneous literal requires ^any`.

**Verify.** `should_fail/strict.lg` fails under `--strict`; the same
file passes without it (`test.sh` passes `--strict` to `strict*`
negative tests).
